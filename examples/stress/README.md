# Сложные входы и регрессии трассировки

Это собственные воспроизводимые тесты. Проверочного файла организаторов нет; воспроизведение именно их
ошибки не заявляется. `competition-with-roads` — прежний **SYNTHETIC** слой.
`competition-osm-roads` — отдельный набор с реальными данными OpenStreetMap, полученными через
`overpass.private.coffee` и OSM API после отказа основного Overpass endpoint.

Основа расширенных конкурсных сцен — «Датасет скорректированный.geojson», SHA-256
`cffb7133419d93fe364a53015a7d3ead289f671cbfaf6f4befe87f2a21914130`.
Файл `docs_dataset/!!!_Датасет.geojson` относится к старой схеме и не заменяет скорректированный набор.
Генератор не изменяет исходный файл. Все его исходные features сохраняются в расширенных сценах.

## Воспроизведение

Полная новая проверка одной командой: генерация из сохранённого OSM snapshot, анализ пяти прежних отказов,
все Java/UI tests, исходный baseline и оба режима всех новых/старых сцен с проверкой детерминизма:

```bash
python3 scripts/verify-universal.py --docker-image maven:3.9.6-eclipse-temurin-11
```

Источник по умолчанию берётся из `ТЗ/Датасет скорректированный.geojson` (имя допускает Unicode-нормализацию).
Можно задать `--source '/другой/путь.geojson'`. Без `--docker-image` используются локальные Maven/Java 11.
Python требует `shapely` и `pyproj`, UI tests — Node. Ничего не устанавливается автоматически.
Только регенерация новых данных: `python3 scripts/generate-universal-datasets.py`.
Она не требует сети; версии библиотек и SHA snapshot указаны в `universal-manifest.json`.
Для выбора новой сцены runner поддерживает `--manifest examples/stress/universal-manifest.json`.

Из корня репозитория, Python 3 с `shapely` и `pyproj`:

```bash
python3 scripts/generate-stress-datasets.py --source '/путь/Датасет скорректированный.geojson'
```

Seed по умолчанию `20261016`. `--density 2` увеличивает плотность, `--restrictions 80` задаёт число дорог,
`--out /tmp/stress` меняет каталог. Версии геометрических библиотек записаны в `manifest.json`;
для побайтного воспроизведения нужны те же версии, seed и параметры. Генерация выполняется в EPSG:32637,
выход — WGS84/CRS84. Проверяются валидность геометрии, уникальность ID и неизменность SHA исходного файла.

Генерация и проверка одной командой при установленных Maven и Java 11:

```bash
python3 scripts/run-stress-suite.py --generate --source '/путь/Датасет скорректированный.geojson'
```

Для Java/Maven в Docker добавьте `--docker-image maven:3.9.6-eclipse-temurin-11`.
По умолчанию проверяются оба режима, по два повтора. Каждый расчёт запускается в отдельной JVM с `-Xmx2g`.
`--scenario routing-fallback --mode PLANAR --repeat 3` выбирает конкретную сцену.
`--timeout 900` — защитный таймаут тестового runner, не лимит ТЗ и не параметр production solver.
Отчёты, результаты, логи и SHA сохраняются в `target/stress-results`; `summary.json` содержит нарушения.
При несовпадении build, результата, числа объектов, ожидаемых подключений или проверок runner возвращает ненулевой код.
Сначала выполняется независимая проверка witness-маршрутов; отсутствие подходящих маршрутов не определяется по картинке.

| `universal-boundary` | Микросегмент контура, почти совпадающие road/tram, касающиеся водоёмы; witness. |

Все witnesses проверяются `ResultValidator` и в PLANAR, и в DEPTH; разбиение, расход/ДУ и стоимость проверяются
также отдельным инженерным oracle при решении сцен. Нет требования сохранить прежний score изменённого входа.

### Происхождение OSM

Сохранённые ответы и SHA: [`osm/provenance.json`](osm/provenance.json).
Данные © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright), ODbL 1.0.
Точное bbox вычисляется из исходного GeoJSON. Выбираются автомобильные классы; pedestrian, footway,
cycleway и traffic_island не превращаются в автомобильные дороги. Исходные IDs, tags и источник ширины
сохраняются в свойствах ограничений. Snapshot дорог имеет собственную дату OSM, отдельную от даты загрузки;
геометрия relations загружена через `/relation/{id}/full`. Это не снимок организаторов.

Готовая `area:highway=primary` сохраняется как площадь. Осевые линии буферизуются в EPSG:32637:
корректный `width` используется в метрах; иначе полная ширина принята 4 м для service/living_street,
6 м для residential/unclassified, 7 м для tertiary, 9 м для secondary, 12 м для primary/trunk/motorway.
Это **приближение для теста, не измеренные габариты**. Модель не реконструирует реальную высоту эстакад:
к добавленному road применяется модель кейса. Слои ограничены bbox с метрическим запасом 100 м;
это охват добавленных данных, не граница поиска трассы. Исходные 144 объекта не обрезаются и не изменяются.

Все 57 пересечений дорог с исходными ОКС перечислены в [`osm-conflicts.json`](osm-conflicts.json).
В этой выборке нет точек `oks_connection_point` внутри новых дорог. Перекрытия зданий сохранены;
для приблизительной ширины их физическая достоверность без натурных данных не установлена.
Ни одно перекрытие не удалялось ради 17/17. Размер набора не увеличивался дублированием координат.

Это допущение генератора, не измеренные ширины. Координаты отражают кривизну и расширения, размер не набран

изменённых конкурсных сцен не фиксируется. Нельзя выпускать недопустимые трассы ради 17/17.

## Подтверждённые дефекты и проверки

- `universal-narrow-corridor`: до исправления 0/1 при валидном witness. Слияние увеличенных навигационных
  буферов закрывало проход. Только после неудачи обычного поиска добавляются вершины более точного
  навигационного буфера; проверка каждого ребра, реальные отступы и независимая валидация не ослаблены.
- `LocalCrossingClearanceTest`: произвольный радиус исключения ошибочно запрещал прямое пересечение
  газопровода под 10° и скрывал короткий параллельный участок после поворота. Теперь исключение ограничено
  связной переходной областью конкретного пересечения на прямом подходе. Поворот завершает исключение,
  соседняя коммуникация проверяется отдельно. Спецучасток и Kспец остаются строго на нормативных ±2 м.
  Проверяются gas/cable/heat при 90°, 45°, 10°, параллельный участок и соседний кабель.

Пять отказов прежней синтетической дорожной сцены разобраны независимо:

| ОКС | Индивидуальный дорожный полигон | Расстояние точки до его границы изнутри, м |
|---|---|---:|
| 2 | stress-road-9 | 0,894 |
| 11 | stress-road-7 | 0,270 |
| 12 | stress-road-7 | 2,421 |
| 15 | stress-road-5 | 1,555 |
| 17 | stress-road-14 | 2,593 |

Каждая точка строго внутри отдельного исходного полигона, а не ошибочного объединения. Любой непрерывный
подход заканчивается внутри дороги, поэтому требуемые 3 м за границей с этой стороны не помещаются.
Точки не лежат на существующей сети; исключение для камер из п. 13 разъяснений к ним не относится.
Другой выход ОКС, tie-in, глубина или обход не устраняют это локальное противоречие.
`SyntheticRoadConflictsTest` проверяет геометрические предпосылки и требует `SECTION_OUTSIDE` от независимого
валидатора для двух направлений присоединения каждого ОКС. Детали, ближайшие выходы и альтернативные
сети: [`synthetic-road-conflicts.json`](synthetic-road-conflicts.json), воспроизведение:
`python3 scripts/analyze-road-conflicts.py`. Доказательство относится только к этой синтетической модели.
В диагностике используется `GENUINELY_UNREACHABLE` только для доказанного локального случая;
`NO_PATH_IN_NAV_GRAPH` и `COMPLEXITY_LIMIT` не означают геометрической невозможности.

- Четыре `routing-fallback*` сцены выявили ложное неподключение при валидном witness:
  терминал не достигал графа за пределами радиуса, первые 40 выходов ОКС были перекрыты либо
  подход обрывался внутри дорожного спецпрохода. Дополнительный поиск продлевает прямой подход до
  геометрических событий окончания спецпрохода, сохраняя угол, отступы и запрет прохода через другое крыло ОКС.
- Дорожная сцена выявила ложные `LINES_INTERSECT`: для раздельных линий с пересекающимися bbox JTS возвращает
  `LINESTRING EMPTY`. Валидатор ошибочно считал этот пустой компонент пересечением. Дефект изолирован на двух
  коротких ломаных в `DisjointEnvelopeValidationTest`; реальные пересечения и сближения проверяются по-прежнему.
- `routing-fallback-road-exit.witness.json` выявил вторую ошибку проверки: технический узел начала
  спецпрохода внутри ОКС ошибочно обрывал финальный прямой подход. Теперь граница подхода определяется
  первым реальным поворотом; разбиение выхода коллинеарными техническими узлами её не меняет.
- `OwnOksTransitValidationTest` выявил запрещённый проход через вторую часть собственного MultiPolygon:
  поиск свободной точки перескакивал через другое крыло здания, а исключение валидатора для прямого
  подхода скрывало повторный вход. Планировщик и независимый валидатор теперь проверяют единственный
  непрерывный выход из собственного ОКС; доступные выходы с других сторон сохраняются.
- Непригодная геометрия ограничения раньше могла исключаться из модели с предупреждением. Теперь вход
  отклоняется с ID объекта; неподдерживаемый GeometryCollection не интерпретируется как линейная коммуникация.
- Численный сбой overlay проверен на минимальном [публичном примере JTS](https://github.com/locationtech/jts/issues/288).
  Этот unit test намеренно использует высокую fixed precision для воспроизведения сбоя; production precision
  не меняется. При `TopologyException` выполняется robust overlay JTS 1.19, исходные объекты не изменяются.
  Неустранимый сбой получает `INTERNAL_GEOMETRY_PROCESSING_FAILURE`, ограничение не пропускается.

Индекс отрезков границ ускоряет точный поиск ближайшего ребра для угла пересечения. При равенстве сохраняется
исходный порядок рёбер; если пересечение не лежит в малой окрестности границы, выполняется полный точный поиск.
Индексы живут внутри расчёта. Формулы стоимости, гидравлика, scoring, формат выхода и правила спецпроходов не меняются.

## Границы поиска и ресурсов

Обычный поиск сохраняется. Только если он не подключил потребителя, fallback проверяет полную выборку внешней
границы, увеличивает радиус видимости терминала, уточняет вершины зон отступа, затем расширяет покрытие сеткой 80/20 м. Кандидаты проходят
независимую валидацию до принятия. Fallback не запускается ради улучшения уже допустимого конкурсного результата.

Бюджеты на класс отступов: 100 000 вершин, 4 млн направленных рёбер, 50 млн проверок видимости.
До выделения рёбер оценивается объём пар; при добавлении вершины лимит проверяется до изменения графа.
Fallback: до 4096 отсчётов границы, 512 событий окончания спецпроходов на луч выхода,
20 000 вершин для расширенной видимости/уточнённого контура и 4096 ячеек на этап сетки.
Превышение обозначается `COMPLEXITY_LIMIT`, а не доказанной геометрической невозможностью.
Это не exact solver: конечная выборка, консервативные классы отступов и бюджеты сохраняют риск пропуска сложного коридора.
Данные больших GeoJSON остаются в памяти после потокового разбора; тесты не доказывают обработку любых 3 ГБ при 16 ГБ RAM.

`routing_intersection_calls` считает overlay-пересечения в routing и подготовке tie-in, но не все операции
независимого валидатора. `sampled_peak_heap_bytes` — максимум используемого Java heap с опросом каждые 5 мс,
не RSS контейнера. Метрики также включают nodes/edges, fallback activations, время и connected/unconnected.
`graph_nodes` и `graph_edges` — состояние графов в конце расчёта, не пик; историческая метрика
`graph_edges` равна половине числа направленных рёбер (с округлением вниз). Бюджет рёбер проверяется
по точному числу направленных записей adjacency.

## Сохранённый baseline

В `baseline/` находятся выходы, отчёты и SHA до изменения production-кода.
PLANAR/DEPTH: 17/17, valid=true, 0 errors/warnings, best score 13.4336.
`CompetitionBaselineTest` сравнивает оба выхода побайтно, когда задан `-Dheatnet.corrected.input=/путь/к/файлу`.
Малые стресс-сцены входят в обычный `mvn test`; крупные запускаются отдельным runner.

## Результаты проверки

Машинно-читаемые итоговые результаты, SHA, подключённые/неподключённые ОКС, причины,
время, sampled heap и команды воспроизведения: [verification.json](verification.json).
Полные журналы отдельных запусков сохраняются в `target/universal-final` и `target/universal-legacy`.
Проверка не подменяет геодезическое согласование приблизительных дорожных площадей с исходными ОКС.

Контроль исходного набора требует 17/17, score 13.4336, 0 ошибок/предупреждений и точного совпадения
обоих файлов в `baseline/`. Для новых входов проверяются геометрия, гидравлика, стоимость,
полнота прочтения объектов, известные допустимые подключения и детерминизм, а не старый score.
Исчерпание конечного поиска или лимита ресурсов всегда отличается от доказанной невозможности.

Тесты не доказывают математическую полноту поиска: остаются дискретная выборка выходов и tie-in,
консервативные классы ДУ, ограниченное расширение графа и ограниченный поиск альтернативных подходов.
Непересекающийся графовый путь может быть отвергнут по углам, топологии или гидравлике; такой отказ
не является доказательством отсутствия всех других инженерно допустимых трасс.
